# Vispace 실물 iPhone 검수 절차

이 문서는 현재 앱 코드에 연결된 기능을 실제 방과 물체로 확인하기 위한 절차다. **모든 항목은 현장 검증 대기 상태다.** 자동 테스트 통과, 시뮬레이터 실행, 카메라 화면 표시만으로 아래 항목을 통과 처리하지 않는다.

정상 결과를 얻은 시험과 정보 부족을 올바르게 처리한 시험을 각각 기록한다. 충분히 관찰한 환경에서도 계속 정보 부족만 표시되면 예외 처리는 확인했더라도 해당 기능의 정상 동작은 **보류**다. 인식 정확도, 재인식 오차, 배치 적합성, 경로 품질은 이 절차를 실행하고 측정하기 전까지 검증된 것으로 표현하지 않는다.

## 시작 전 준비

- 실제 설치한 빌드의 버전·빌드 번호·소스 커밋 또는 변경본 식별자, iPhone 모델, iOS 버전, LiDAR 지원 여부, 시험 날짜와 담당자를 기록한다. 디버그용 모의 카메라·권한·AR 비활성화 인수를 사용하지 않는다.
- 밝고 사람이 이동할 공간이 있는 방에서 시작한다. 바닥·벽·테이블과 노트북을 준비하고, 서로 같은 종류의 물체가 여러 개 있는 시험은 따로 수행한다. 별칭 표에 이름이 있다는 사실만으로 모델이 그 종류를 인식한다고 판정하지 않는다. 실제 인식된 라벨을 기록한다.
- 물체 위치 A/B와 가구 후보 영역, 출발 지점을 표시하고 줄자로 기준 거리를 잰다. 기능 확인 전에는 경로 표시만 믿고 이동하거나 실제 가구를 옮기지 않는다.
- 데이터 삭제 시험에는 시험용 기록을 사용한다. 전체 삭제 확인을 누르면 이 iPhone의 저장된 지도·물체 위치·관계·기록이 실제로 삭제된다.
- 화면 관찰 외에 저장 여부나 물체 ID를 확인할 때는 개발자가 Xcode의 앱 컨테이너 또는 디버거에서 읽기 전용으로 조사한다. 앱에는 수동 체크포인트 저장 버튼, 개별 관측의 저장 완료 표시, 물체 ID 목록이 없다. 설정에서는 장소별 최신 지도와 현재 물체 기록을 암호화해 내보내고 가져올 수 있지만 전체 시간 이력은 포함하지 않는다.

현재 입력은 하단 텍스트 입력창과 키보드의 검색 또는 입력창의 보내기 버튼을 사용한다. 마이크나 자유 대화 기능은 이 절차의 대상이 아니다. 결과 카드의 X는 현재 결과·배치 미리보기·안내를 닫는다. 톱니바퀴는 **공간 데이터**, 격자 모양 가구 메뉴는 **가구 배치 확인**이다.

## 1단계 — 첫 실행, 권한, 카메라와 공간 저장

### 절차

1. 첫 실행 상태에서 앱을 연다. **내 공간을 기억하는 도우미** 소개에서 물건 찾기·공간 질문·가구 배치와 길 안내를 확인한다. 촬영 방법을 읽고 **동의하고 카메라 시작**을 누른 뒤 시스템의 카메라 접근을 허용한다.
2. iPhone을 세로로 들고 바닥·벽·가구를 천천히 여러 각도에서 비춘다. 한 지점만 바라보는 경우와 주변을 충분히 둘러본 경우를 구분해 기록한다.
3. 화면에 실제 카메라 영상과 하단 입력창이 표시되는지 확인한다. 홈 화면으로 나갔다 돌아오기, 화면 잠금 후 복귀를 반복한다.
4. 충분히 매핑된 상태에서 홈 화면으로 나갔다가 돌아온다. 개발자는 전용 저장소 `Library/Application Support/Vispace/SpatialCapture`의 `spatial-metadata-v1.json`과 연결된 지도 저장 기록을 읽어 체크포인트의 실제 저장을 확인한다. 저장 확인 뒤 앱을 종료하고 같은 방에서 다시 연다.
5. 같은 방의 특징을 다시 비춰 재인식한 뒤, 다른 방에서도 재실행한다. 같은 방 복구와 다른 방의 새 세션을 구분해 지도·좌표 식별자와 복구 결과를 기록한다.

### 예상 결과와 통과 조건

- 동의 전 카메라 시작을 요구하지 않고, 동의·권한 허용 뒤 영상이 나타난다. 두 번째 일반 실행에서는 완료한 첫 설명을 반복하지 않는다.
- 공간 매핑이 충분한 상태에서 자동 체크포인트가 저장된다. 자동 저장은 ARKit의 매핑 상태와 실행 조건에 따르므로 특정 대기 시간만으로 저장 완료를 판정하지 않는다.
- 재실행 후 같은 방에서 저장 기록을 읽고 좌표를 재확인할 수 있다. 다른 방을 이전 방과 잘못 연결하지 않는다. 홈·잠금 복귀 뒤 카메라와 새 공간 관찰이 다시 동작한다.

### 실패·제한 시험

- 카메라 권한을 거부하면 **카메라 접근이 꺼져 있어요**와 **설정 열기**가 표시되어야 한다. 설정에서 Vispace 카메라 권한을 허용하고 돌아오면 다시 시작할 수 있어야 한다.
- 권한이 거부된 화면에서도 **공간 데이터 관리**로 데이터 설정을 열 수 있어야 한다. 카메라가 불가하거나 세션이 실패한 경우에는 해당 설명과 **다시 시도**가 보여야 한다.
- 지도 저장이 없거나 좌표 복구가 실패하면 이전 위치에 임의의 AR 표시를 붙이지 않아야 한다. 저장 성공과 좌표 재인식 성공은 별도로 판정한다.
- 비LiDAR 기기는 별도 회차로 기록한다. 카메라가 열린다고 깊이·메시가 있는 것으로 판정하지 않는다.

## 2단계 — 물체 인식과 지속 저장

### 절차

1. 테이블 위에 노트북 하나를 놓고 물체와 주변을 여러 각도에서 비춘다. 하단에 `노트북 찾아줘`를 입력한다.
2. 개발자는 확정된 저장 물체의 라벨·물체 ID·지도 ID·좌표·3D 범위·관찰 시각을 확인한다. 검출되었지만 아직 확정되지 않은 후보와 저장 물체를 구분한다.
3. 같은 노트북을 다른 각도·거리에서 관찰한 뒤 다시 검색한다. 잠깐 다른 곳을 비췄다가 돌아온 경우도 반복한다.
4. 같은 종류의 물체 두 개를 함께 관찰하고 검색한다. 가려짐과 조명 변화도 각각 독립적으로 시험한다.
5. 저장을 확인한 뒤 앱을 재실행하고 같은 방에서 다시 검색한다. 이전 물체 기록이 남아 있는지, 동일 물체를 반복 생성하거나 서로 다른 물체를 합치지 않는지 ID로 확인한다.

### 예상 결과와 통과 조건

- 충분한 인식·깊이·좌표 근거가 쌓인 물체만 영속 기록에 반영된다. 재관찰과 재실행 후 기록을 조회할 수 있고, 위치가 실제 대상과 대응한다.
- 같은 종류가 여럿이라 구분할 수 없으면 후보 목록과 **찾으려는 물체를 선택해 주세요** 안내를 한다. 선택 전에는 하나를 임의로 확정하지 않고, 선택 후에는 최신 기록과 좌표·신뢰도를 다시 확인한다.
- 인식된 종류, 성공/실패 횟수, 중복 ID, 잘못 합쳐진 ID, 기준 위치와의 오차를 기록한다. 노트북 예시의 인식 성공을 다른 모든 물체 종류의 성공으로 확대하지 않는다.

### 실패·제한 시험

- 저장된 대상이 없으면 저장 위치를 찾지 못했다는 안내가 나와야 한다. 불확실한 깊이나 가려진 물체를 확정 좌표로 저장하면 실패다.
- **물체 인식을 사용할 수 없어요** 배너가 있으면 새 물체 인식·저장 시험은 보류한다. 기존 공간 검색과 데이터 관리는 별도로 확인할 수 있지만 새 물체 인식 성공으로 기록하지 않는다.

## 3단계 — 물체 검색과 AR 위치 안내

### 절차

1. 확정된 노트북을 대상으로 `노트북 찾아줘`를 입력한다. `휴대폰 어디 있어?`는 실제 휴대폰 기록이 있을 때만 추가 시험한다.
2. 대상을 화면 앞에 둔 경우, 화면 밖에 둔 경우를 나누어 폰을 천천히 돌린다. 물체 이름·거리·신뢰도 표시와 대상 마커 또는 방향 표시가 실제 위치에 대응하는지 확인한다.
3. 결과 카드의 X로 닫고 모든 관련 표시가 사라지는지 확인한다. 연속으로 다른 검색을 요청했을 때 이전 결과가 뒤늦게 다시 나타나는지도 확인한다.
4. 검색 결과가 있는 상태에서 홈 화면 또는 잠금 화면으로 갔다 돌아온다. 재인식되지 않은 좌표나 이전 세션의 표시가 계속 남지 않는지 확인한다.

### 예상 결과와 통과 조건

- 확정된 현재 공간과 연결되는 대상만 AR 위치 안내를 받는다. 검색 문구에 “안내를 시작할 수 있어요”가 포함되어도 별도의 시작 버튼을 찾을 필요는 없다. 현재 UI는 확정된 검색 결과를 자동으로 안내 화면에 연결한다.
- 화면 밖 대상에는 방향 표시를, 조건에 맞는 화면 내 대상에는 월드 마커를 보여준다. 거리와 방향을 실제 측정값과 비교한다.
- 기록을 찾았다는 사실과 AR 좌표를 표시할 수 있다는 사실을 분리해 보여준다. 조회 시간·첫 안내 표시 시간·거리/방향 오차를 기록한다.

### 실패·제한 시험

- 좌표 연결이 없거나 위치 신뢰도가 낮으면 이유를 안내하고 AR 위치를 표시하지 않아야 한다.
- 대상 없는 질문이나 지원하지 않는 복잡한 요청은 이해하지 못했거나 지원 범위에 해당하지 않는다는 응답이어야 한다. 존재하지 않는 물체나 설명을 만들어내면 실패다.
- 물체 검색의 방향 표시는 장애물을 피하는 실내 경로 검증과 별개다. 6단계의 길 안내 통과로 계산하지 않는다.

## 4단계 — 공간 관계와 소파 배치

### 관계 질문 절차

1. 테이블 위 노트북과 테이블을 각각 충분히 관찰하고 두 물체가 저장되었는지 확인한다. `테이블 위에 뭐가 있어?`를 입력한다.
2. `노트북이 테이블 위에 있어?`로 두 물체 관계를 확인한다. 이 예시는 텍스트에서 먼저 언급한 노트북을 주체, 테이블을 기준 대상으로 해석한다.
3. 노트북을 테이블에서 치워 다른 위치에 놓고 이전 자리와 새 자리를 다시 관찰한다. 같은 질문을 다시 입력한다.

확정된 최신 관계가 있으면 해당 물체를 답하고, 없으면 **현재 확정된 기록에서는 해당 위에 관계를 확인하지 못했어요**와 같이 답해야 한다. 물체가 이동한 뒤 이전 관계를 계속 확정해 답하면 실패다. 동일 종류가 여러 개이면 관계도 모호하다고 답할 수 있다. 관계가 없다는 응답은 물리적으로 관계가 절대 없다는 증명이 아니다.

### 소파 배치 절차

1. LiDAR 기기에서 바닥·벽·문·주변 물체·통로를 넓게 비춘 뒤, 소파를 둘 후보 바닥을 화면 중앙에 둔다.
2. 격자 모양 **가구 배치 확인** 메뉴에서 **소파**를 선택하고, 치수 입력 화면에서 실측한 폭·깊이·높이를 입력한 뒤 배치 평가를 실행한다. 같은 위치에서 `여기에 소파 놓으면 어때?`를 입력해 동일한 치수 입력과 평가로 연결되는지도 확인한다.
3. 넓게 비어 있는 후보, 기존 물체와 겹치는 후보, 벽에 너무 붙은 후보, 문이나 좁은 통로를 가리는 후보를 각각 확인한다. 후보를 바꾸려면 화면 중앙을 새 바닥 위치에 맞춰 다시 요청한다.
4. 배치가 가능하다고 판정된 경우 반투명 가구 미리보기의 바닥 접촉·위치·규모를 실제 공간과 비교한다. 결과를 닫거나 추적이 끊기면 미리보기가 정리되는지 확인한다.

### 예상 결과와 통과 조건

- 이 화면은 한 후보 위치에 사용자가 확인한 치수의 가구가 들어갈지 평가한다. 치수 입력의 초기값은 소파 **폭 2.0m × 깊이 0.9m × 높이 0.9m**, 침대 1.6 × 2.0 × 0.6m, 책상 1.4 × 0.7 × 0.75m이며 수정할 수 있다. 현재 UI에는 회전 손잡이·상품 선택 기능이 없다.
- 바닥 지지·벽·문·물체·통로 근거를 충족할 때만 적합 메시지와 반투명 미리보기를 표시한다. 실제 소파의 미관·스타일·가격 추천이나 방 전체의 최적 배치 결과로 해석하지 않는다.
- 충돌, 벽 여유 부족, 통로 좁아짐, 출입 공간 방해를 각각 거절하는지 기록한다. 실제로 놓을 수 없는 후보에 적합 판정이 나오면 실패다.

### 실패·제한 시험

- 바닥이 화면 중앙에서 확인되지 않으면 **바닥을 비춰 주세요**라는 안내가 나와야 한다. 스캔·LiDAR·빈 공간 근거가 부족하면 추천하지 않았다는 이유를 보여야 한다.
- 충분한 환경에서도 적합 사례를 한 번도 만들지 못하면 배치 정상 동작은 보류한다. 정보 부족 메시지의 올바른 표시만 통과 처리한다.

## 5단계 — 마지막 확인 위치, 이동, 재실행과 삭제

### 기억과 이동 절차

1. 노트북을 위치 A에서 확정 저장하고 `노트북을 마지막으로 어디에서 봤어?`를 입력한다. 질문마다 대상 이름을 포함한다. 현재 입력창은 “그거”를 이전 질문의 대상으로 이어 받는 대화 UI가 아니다.
2. 노트북이 잠시 카메라 밖에 있는 경우와 실제로 위치 B로 옮긴 경우를 나누어 시험한다. 이동 시험에서는 A의 빈 자리와 B의 물체를 다시 비춘다.
3. 현재 검색과 마지막 확인 위치 검색을 각각 수행한다. 개발자는 물체 ID, 현재 존재 상태, 마지막 관찰 시각, 이동 이력과 저장 좌표가 구분되어 갱신되는지 확인한다.
4. 앱을 재실행한 뒤 같은 질의를 반복한다. 마지막 확인 위치는 현재 존재를 보장하는 표시로 바뀌면 안 된다. 좌표 재인식이 안 되면 기록은 찾더라도 AR 위치 표시를 보류해야 한다.

### 데이터 삭제 절차

1. 톱니바퀴 → **공간 데이터**에서 로컬 저장·원본 프레임 미저장·삭제 전 보관 안내를 확인한다.
2. **공간 데이터 모두 삭제** → **취소**를 선택한다. 기존 기록을 다시 조회할 수 있어야 한다.
3. 시험용 기록에서 다시 삭제를 선택하고 **완전히 삭제**를 누른다. **공간 데이터 삭제 중…** 상태와 완료 메시지를 확인한다. 삭제 중에는 중복 삭제, 완료 버튼, 화면을 쓸어내려 닫기가 허용되지 않아야 한다.
4. 별도 회차에서는 검색이나 배치 계산을 요청한 직후 삭제하고, 또 다른 회차에서는 삭제 중 홈 화면으로 나갔다 돌아온다. 실제 삭제가 너무 빨라 중간 상태를 관찰하지 못했다면 해당 경합 시험은 보류로 기록한다.
5. 삭제 완료 뒤 카메라를 새로운 물체가 없는 쪽으로 둔 상태에서 기존 노트북을 검색한다. 이전 기록과 AR 표시가 되살아나지 않아야 한다. 개발자는 삭제 전 지도·물체·관계·이력 식별자가 전용 저장소에서 사라졌는지 확인한다.
6. 앱을 재실행해 기존 기록이 복원되지 않는지 확인하고, 새 물체를 관찰해 새 공간 기억을 만들 수 있는지 확인한다. 이어서 6단계를 진행하려면 공간과 목적지를 다시 충분히 스캔한다.

### 예상 결과와 실패 시 동작

- 삭제는 진행 중인 관찰·조회·계산·저장을 정리한 뒤 전용 공간 저장소를 비운다. 완료 후 활성 앱에서는 새 지도 세션을 시작하고, 백그라운드 상태라면 복귀 후 촬영을 재개한다.
- 새 스캔이 시작되면 전용 폴더에 새 파일이 생길 수 있다. 따라서 폴더가 영구히 비어 있는지가 아니라 **삭제 전 기록이 돌아오지 않는지**를 판정한다.
- 삭제 실패 시 **공간 데이터를 삭제하지 못했습니다. 다시 시도해 주세요.**가 표시되어야 한다. 완료 표시가 뜨지 않아야 하며, 개발자는 남아 있는 파일을 조사한다.
- 첫 실행 설명 완료 설정과 iOS 카메라 권한 초기화는 공간 데이터 삭제 기능에 포함되지 않는다. 삭제 후 설명이 다시 뜨지 않는 것을 실패로 보지 않는다.
- 원본 카메라 프레임 미저장과 자동 외부 전송 없음은 화면만으로 입증하지 않는다. 실제 앱 컨테이너와 실행 중 네트워크 관찰을 별도로 남긴다. 사용자가 Files로 내보낸 암호화 장소 파일과 검수자가 만든 화면 캡처는 앱의 자동 저장·전송과 구분한다.

## 6단계 — 검증된 실내 길 안내

### 절차

1. LiDAR 기기에서 출발점부터 목적지 주변까지 바닥·벽·장애물을 연속적으로 스캔한다. 같은 확정 지도에 현재 물체로 기록된 목적지 노트북을 준비한다.
2. `노트북까지 안내해줘`를 입력한다. 먼저 물체가 확정 검색되고 이후 길 안내가 계산되는 흐름을 확인한다.
3. 경로가 나오는 경우 청록색 경로 표시가 바닥과 맞고 벽·가구를 통과하지 않는지 정지 상태에서 확인한다. 실제 이동 전에 관찰자가 통로를 확인하고, 이동 중 거리와 경로 정렬을 기록한다.
4. 장애물이 없는 경우, 물체로 통로를 막은 경우, 목적지 접근이 막힌 경우를 나누어 다시 스캔하고 요청한다. 안내 중 장애물이 바뀌면 이전 경로가 폐기되거나 최신 근거로 다시 계산되는지 확인한다.
5. 바닥 일부를 스캔하지 않은 경우, 여러 높이의 바닥이 보이는 경우, 문이 관찰되는 경우를 별도로 시험한다. 문을 열어 둔 경우도 포함한다.
6. 경로가 있는 상태에서 폰을 급격히 돌리거나 잠시 가려 추적이 불안정해지는 상황, 홈·잠금 전환, 결과 X 닫기를 각각 시험한다. 다시 안정적으로 스캔하고 재요청할 수 있는지 확인한다.

### 예상 결과와 통과 조건

- 경로와 거리 메시지는 현재 위치·대상·바닥·장애물·좌표·표면 갱신 정보가 검증된 경우에만 나온다. 표시한 경로의 실제 통과 가능성, 위치 오차, 경로 계산 시간과 갱신 시간을 기록한다.
- 통로가 막혔으면 확인된 경로가 없다는 안내가 나와야 한다. 공간 근거가 부족하면 바닥·통로를 더 비추라는 안내가 나와야 하며 임의의 직선 경로를 표시하면 실패다.
- 현재 코드에는 문 열림을 확정하는 별도 입력이 없다. 문 형상이 보이거나 실제 문이 열려 있어도 통과 가능한 문으로 확정하지 않으며, 해당 구간의 안내를 보류할 수 있다. 문 통과 성공을 필수 지원 기능으로 기록하지 않는다.
- 추적 제한, 지도 변경, 오래된 검색 결과, 다른 좌표의 대상에는 기존 경로를 유지하지 않아야 한다. 마지막 확인 위치 검색을 현재 목적지 길 안내로 바꾸지 않아야 한다.
- 넓고 충분히 관찰한 시험 공간에서도 경로를 만들지 못하면 정상 길 안내는 보류다. 정보 부족·경로 없음 처리를 확인한 것과 구분한다.

## 결과 기록

### 위험 보고서 수정 후 추가 검수

- 물체 검색 뒤 실제 물체를 옮기거나 제거한다. 기존 표식과 결과가 철회되는 시간, 새 검색의 위치 오차를 기록한다. 카메라를 멈춘 채 30초 이상 기다려 기존 표식이 만료되는지도 확인한다.
- 경로 표시 뒤 25cm 이상 이동하고 목적지에 접근한다. 경로·거리 재평가와 도착 처리를 기록한다. 현재 발밑 구역은 최근 스캔 이력을 사용하므로 실제 출발점에서 경로를 생성하는 정상 성공 시험을 반드시 포함한다.
- 새 사람·장애물이 경로에 들어오는 경우, 물체가 센서 해상도보다 작은 경우, 현재 시야 밖에서 들어오는 경우를 나누어 기록한다. 최신 장애물이나 가림을 과거 빈 공간으로 덮어쓴 경우 실패다. 3초 이력이 있다는 이유로 현재 안전을 보장한다고 기록하지 않는다.
- 설정에서 개별 장소 복원과 삭제를 반복한다. 다른 장소의 지도·물체가 유지되는지, 작업 중 홈 화면으로 나가도 이전 결과·캐시가 다시 나타나지 않는지 확인한다. 전체 삭제와 손상 격리본의 보존 범위를 구분한다.
- 저장 실패 배너와 복원 실패 배너를 각각 재현한다. 새 지도 저장에 성공했다는 이유로 기존 지도 복원 실패가 숨겨지면 실패다. 낮은 여유공간에서 개별 장소를 삭제한 후 새 기록 저장이 재개되는지 확인한다.
- 정상본과 직전 metadata 복구본을 각각 손상시킨 조합을 기록한다. 더 새로운 schema를 낮은 버전 앱으로 열었을 때 원래 데이터가 이동·덮어쓰기되지 않는지 확인한다.
- 가구 메뉴와 텍스트 배치 명령 모두 실측 입력을 거치는지 확인한다. 빈 값, 잘못된 문자, 범위를 벗어난 값, 소수점 쉼표 locale을 시험하고 이전 숫자가 대신 제출되면 실패다.
- 앱 전환 화면에서 카메라와 공간 설정 시트를 각각 열어 둔 채 나간다. 실제 app-switcher 미리보기와 잠금 복귀에서 주변 공간이나 저장 정보가 보이지 않는지 확인한다. Simulator 창 덮개 단위 시험은 이 시험을 대신하지 않는다.
- 저전력 모드와 발열 단계에서 추론 시작 간격, 카메라 프레임 유지, 정상 온도 복귀를 측정한다. 반복 스캔·장소 전환·삭제 후 최대 메모리, 기기 온도, 배터리 감소량, 저장 및 검색 지연의 실제 값을 남긴다.

자동 검사 통과 여부와 위 정상 성공·예외 회복 시험의 결과를 별도로 기록한다. [항목별 조치 기록](AUDIT_REMEDIATION_2026-09-05.md)에 남은 미구현·검증 조건이 있으면 해당 항목을 출시 완료로 표시하지 않는다.

### 이번 리팩터링의 추가 검수

- 기존 데이터가 있는 상태에서 카메라 권한을 거절해도 저장 루트의 백업 제외 정책이 적용되는지 확인한다. 새 저장·기존 저장 조회·격리·삭제 후 재생성 경로의 `isExcludedFromBackup`과 실제 File Protection 속성을 기기에서 읽는다. Simulator의 nil 속성을 실기기 검증 통과로 계산하지 않는다. 과거 OS 백업의 삭제는 앱 검수 범위가 아니다.
- `소파와 침대 배치`, `소파 놓지 마`는 임의의 배치를 실행하지 않아야 한다. `마지막으로 소파를 어디 놓았어?`, `소파가 놓인 곳으로 안내해 줘`는 각각 마지막 관측·안내로 분기해야 한다. 결과를 닫은 뒤 가구 메뉴로 다시 요청할 수 있어야 한다.
- 실제 스캔한 바닥이 삼각형·오목한 모양이거나 구멍/미관측 부분을 포함할 때, 외곽 사각형 안이라는 이유로 배치 가능이 되면 실패다. 방 전체보다 작은 관측 메시라도 후보와 통로가 충분히 확인된 경우 정상 추천도 별도 검증한다.
- 최소 가구 면적만 관측한 경우를 실제 좁은 통로와 구분한다. 주변 통로를 모르면 정보 부족이어야 하며, 좁다고 단정하지 않아야 한다.
- 관계 저장을 512회 이상 갱신해도 새 변경이 저장되는지 확인한다. 물체 이동 시 위치와 충돌 경계 상자가 함께 움직여야 한다.
- 출발점과 인접한 빈 셀 사이에 벽·장애물·미관측 구역을 두고 안내가 이를 건너뛰지 않는지 확인한다. 최신 카메라 위치가 약간 이전의 지도 시각보다 새롭다는 이유만으로 항상 거절되면 실패다.
- 삭제 중 홈 화면으로 나갔다가 삭제가 끝난 뒤 돌아오는 시험과, 저장소 오류 후 재시도 시험을 수행한다. 삭제 전 데이터의 재유입·중복 캡처·백그라운드 자동 재시작이 없어야 한다.

각 세부 시험은 **대기 / 통과 / 실패 / 보류** 중 하나로 기록한다. “보류”에는 부족한 기기 기능·인식·지도·관찰 자료를 적는다. 실패를 재시험할 때는 이전 기록을 지우지 않고 빌드 식별자와 재시험 결과를 추가한다.

| 5 | 마지막 위치·이동·복구·삭제 | 삭제 취소·진행 중 전환·실패 | 삭제 전후 ID, 시간 정보, 컨테이너 관찰 | 현장 검증 대기 |
| 6 | 확인된 경로·갱신 | 막힘, 미관찰 바닥, 문, 추적 제한 | 실제 경로, 계산 시간, 경로 오차 | 현장 검증 대기 |

시험별 기록에는 빌드·기기·방/배치·정확한 입력·사전 데이터·조작·실제 응답·소요 시간·증거 파일·판정을 포함한다. 정량 합격 기준이 아직 승인되지 않은 항목은 측정값만 기록하고 임의의 정확도 보장을 붙이지 않는다.
