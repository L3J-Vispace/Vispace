## 저장 형식과 복구

- 저널 카탈로그는 스키마 4다. 기존 스키마 1–3을 읽으며, 내부 Core 스냅샷은 최대 스키마 3으로 별도 검증한다. 더 새로운 루트·내부 스키마는 원본 파일을 이동하거나 덮어쓰지 않는다.
- 삭제된 이력 정리는 저널의 정리 의도 기록 → 정확히 일치하는 메타데이터와 관계 삭제 → 저널 완료 기록 순서다. 중단되면 다음 복구에서 이어서 처리한다. 메타데이터의 복구본도 삭제 내용으로 먼저 갱신한다.
- 지도 용량 정리는 새 지도 저장이 용량 한도에 걸릴 때에만 수행하며, 같은 장소의 검증된 최신 복원점 두 개와 해석할 수 없는 파일은 보존한다. 관련 없는 파일은 정리하지 않는다.
- 지도 저장 전 메타데이터 게시에 필요한 추가 공간도 검사한다. 이는 다른 저장소의 동시 쓰기에 대한 지속적인 공간 예약은 아니다. 이후 디스크 부족·I/O 실패는 여전히 발생할 수 있으며, 이 경우 기존 복원점을 보존한다.
- 전송 형식 2의 한도는 지도 128 MiB, JSON 매니페스트 16 MiB, 전체 파일 146 MiB, 전체 물체 65,536개 및 자동 물체 2,048개다. 실제 입력은 바이트·스키마·물체 수·좌표·인증·ARWorldMap 형식 검증을 모두 통과해야 한다. 입력과 출력 버퍼는 메모리에 남으므로 암호화 단위가 작다는 이유로 일정한 메모리 사용을 보장하지 않는다.

## 롤백

기능별 수정 커밋을 되돌릴 수 있으나, 스키마 4를 작성한 데이터에 구형 앱을 바로 설치하면 읽기를 거절한다. 저장 데이터를 유지하려면 스키마 4 읽기와 진행 중인 정리 복구를 지원하는 버전에서 기능만 되돌려야 한다. 구형 앱을 위해 데이터를 삭제하거나 스키마 숫자만 낮추면 안 된다. 새 전송 파일도 형식 2를 지원하는 앱에서 가져와야 한다.

실제 경로 안전성·장소/깊이 정확도·장시간 안정성, 계정 결제 상태 및 장기 서명은 코드 검사 통과만으로 완료 처리하지 않는다.
