# 위험 예외 보안 보고서 조치 기록

첨부 보고서의 기준 커밋 `88f621d`에서 지적한 22개 항목을 실제 코드와 대조했다. 아래 표는 코드 변경, 기능 지원 범위, 실기기 검증을 구분한다. 이 문서는 모든 결함이 사라졌다거나 출시 검수가 끝났다는 보증이 아니다.

## 보안 경계

- S01–S04: Files로 직접 고른 암호화 장소 파일만 가져온다. AES-256-GCM 인증과 별도 무작위 복구 키, 길이 제한, secure coding, 좌표·ID·체크섬 검증을 적용한다. 기존 데이터는 덮어쓰지 않고 새 blob과 metadata를 원자적으로 게시한다. 자세한 범위는 [장소 이전 형식](Spatial-place-transfer.md)에 기록했다.
- S05: 저장·읽기·교체·삭제 경로의 symlink와 파일 종류를 검사한다. 전체 삭제는 Vispace 전용 경로에만 적용한다.
- S06: 파일 보호와 OS 백업 제외를 유지한다. 실제 잠금 상태와 과거 OS 백업 사본은 기기에서 확인해야 한다.
- S07: 앱 비활성화 알림에서 카메라와 시트를 포함한 창을 동기적으로 가린다. 복귀 시 덮개를 제거한다. 구현 기준은 [Apple의 백그라운드 UI 및 스냅샷 문서](https://developer.apple.com/documentation/uikit/preparing-your-ui-to-run-in-the-background)다.
- S08: Windows 검증용 Swift 컨테이너를 registry에서 확인한 immutable digest로 고정했다. 기존 Action/XcodeGen/모델 검증을 유지한다.

## 검증 기록

원격 Mac에서 초기 변경본의 코어 XCTest 307개와 Swift Testing 9개가 통과했다. 해당 코어 파일 두 개의 SHA-256이 로컬과 동일함을 확인하고 `b5b7a44`로 커밋했다. 이후 iOS 앱 컴파일은 통과했으며 테스트 코드의 Swift 동시성 진단을 수정했다. Mac이 오프라인으로 전환되어 최종 통합 검증은 GitHub Actions에서 이어간다. 초기 실행 결과를 이후 변경 전체의 통과 증거로 합산하지 않는다.

`ebdd399`의 GitHub CI에서 코어, Debug·Release 빌드, 최적화 리소스 검사, 서명 없는 기기 archive가 통과했다. 시뮬레이터 검사는 6개 테스트에서 실패했다. 이전 timestamp 재사용 fixture, 동일성 검증이 빠진 합성 fixture, 조기 symlink 거부 오류 기대값, 치수 입력 단계·설정 스크롤을 반영하지 않은 UI 검사를 수정했다. 해당 실행을 전체 통과로 집계하지 않는다.

시계 자동 복구, 암호화 이전, 물체 선택·이름 지정과 위 실패 수정의 최종 통합 CI 결과는 확인 후 이 절에 기록한다.

## 영향과 롤백

변경은 로컬 공간 저장, 인식·검색·배치·안내, 앱 생명주기와 설정 화면에 영향을 준다. 저장과 경로 안내의 동작을 바꾸므로 위험도는 높음으로 취급하며 실기기 검수가 끝나기 전 출시 완료를 주장하지 않는다.

문제 발생 시 해당 기능 커밋을 `git revert`하고 CI를 다시 실행한다. 기존 데이터는 먼저 보존한다. `reset --hard`, 강제 push, 이력 재작성은 롤백 방법으로 사용하지 않는다. 직전 metadata 복구본은 앱의 로컬 손상 복구 수단이며 소스 코드 롤백과는 별개다.

시계 복구의 설계와 B08의 남은 조건은 [시간 기록과 재식별 보완 기록](TEMPORAL_RELIABILITY_2026-09-05.md), 실제 기기 합격 조건은 [실기기 검수표](DEVICE_ACCEPTANCE.md)에 있다.
