## 보안 경계

- S01–S04: Files로 직접 고른 암호화 장소 파일만 가져온다. AES-256-GCM 인증과 별도 무작위 복구 키, 길이 제한, secure coding, 좌표·ID·체크섬 검증을 적용한다. 기존 데이터는 덮어쓰지 않고 새 blob과 metadata를 원자적으로 게시한다. 자세한 범위는 [장소 이전 형식](Spatial-place-transfer.md)에 기록했다.
- S05: 저장·읽기·교체·삭제 경로의 symlink와 파일 종류를 검사한다. 전체 삭제는 Vispace 전용 경로에만 적용한다.
- S06: 파일 보호와 OS 백업 제외를 유지한다. 실제 잠금 상태와 과거 OS 백업 사본은 기기에서 확인해야 한다.
- S07: 앱 비활성화 알림에서 카메라와 시트를 포함한 창을 동기적으로 가린다. 복귀 시 덮개를 제거한다. 구현 기준은 [Apple의 백그라운드 UI 및 스냅샷 문서](https://developer.apple.com/documentation/uikit/preparing-your-ui-to-run-in-the-background)다.
- S08: Windows 검증용 Swift 컨테이너를 registry에서 확인한 immutable digest로 고정했다. 기존 Action/XcodeGen/모델 검증을 유지한다.

## 검증 기록

원격 Mac에서 초기 변경본의 코어 XCTest 307개와 Swift Testing 9개가 통과했다. 해당 코어 파일 두 개의 SHA-256이 로컬과 동일함을 확인하고 `b5b7a44`로 커밋했다. 이후 iOS 앱 컴파일은 통과했으며 테스트 코드의 Swift 동시성 진단을 수정했다. Mac이 오프라인으로 전환되어 최종 통합 검증은 GitHub Actions에서 이어간다. 초기 실행 결과를 이후 변경 전체의 통과 증거로 합산하지 않는다.

`ebdd399`의 GitHub CI에서 코어, Debug·Release 빌드, 최적화 리소스 검사, 서명 없는 기기 archive가 통과했다. 시뮬레이터 검사는 6개 테스트에서 실패했다. 이전 timestamp 재사용 fixture, 동일성 검증이 빠진 합성 fixture, 조기 symlink 거부 오류 기대값, 치수 입력 단계·설정 스크롤을 반영하지 않은 UI 검사를 수정했다. 해당 실행을 전체 통과로 집계하지 않는다.

`c5a8a6b`에서는 코어 XCTest 318개와 Swift Testing 9개, Debug·Release 빌드, 최적화 리소스 검사와 서명 없는 기기 archive가 통과했다. 시뮬레이터 테스트 target의 `SceneGraph` 비교문 컴파일 오류는 `5baeae0`에서 정렬된 관계 값 비교로 수정했다. 이 실행 역시 전체 통과로 집계하지 않는다.

최초 장소 가져오기·지도 저장의 기본 파일 게시가 실패하면 복구 사본이 실패한 새 blob을 참조하지 않도록 이전의 빈 상태를 기록한다. 기본 파일 게시 이후의 첫 복구 사본 갱신 실패는 이미 저장된 blob을 되돌리지 않는다. 기본 파일 실패와 게시 이후 유지관리 실패를 각각 재현하는 회귀 검사를 추가했다.

`2dec50d`의 [통합 실행](https://github.com/L3J-Vispace/Vispace/actions/runs/33944564203)은 Core 327개, 시뮬레이터 417개, Debug·Release, 최적화 리소스, 무서명 기기 archive 및 Analyze를 통과했다. 시뮬레이터에서 구현하지 않는 실기기 Data Protection 검사 1개는 건너뛰었다. 이전 장소 인식 timeout이 이번 실행에서 재현되지 않은 것만으로 원인이 해소됐다고 판단하지 않았다.

후속 검토에서 영구 저장 완료와 writer 반환 사이에 새 프레임이 들어오면 메모리의 이전 revision을 재사용할 수 있는 경합을 확인했다. 실제 저장 후 반환을 차단하는 회귀 2개로 동일 이력의 갱신과 64개 이력 교체 경계를 강제하며, 전체 관측 prefix 보존과 다음 관측의 처리도 확인한다. CI는 130회 관측으로 이력 한도를 넘기는 검사를 추가로 최대 5회 반복하고 첫 실패에서 중단한다. 이 반복은 통과할 때까지 실패를 재시도하는 방식이 아니며 [Apple의 테스트 반복 기능](https://developer.apple.com/videos/play/wwdc2021/10296/)을 사용한다.

`3f02baf`의 [실행](https://github.com/L3J-Vispace/Vispace/actions/runs/33945963853)은 Core 327개와 시뮬레이터 419개를 통과했고 실기기 보호 검사 1개를 건너뛰었다. 별도 반복 검사 첫 회는 125번째 관측을 처리 중인 상태에서 테스트의 관측별 2초 폴링 한도를 넘겨 실패했다. 124회 저장 완료, 미처리 작업 1개, stale·coalesced 0개였으며 저장 오류는 보고되지 않았다. 이 로그만으로 느린 구간이 CPU·파일 I/O·스케줄링 중 어디였는지는 확정하지 않는다.

해당 기능 검사는 관측 수신 후 실제 처리 작업이 끝날 때까지 join하고 완료된 저장 수·오류·최종 영구 이력을 확인하도록 바꿨다. 성공과 실패 모두 작업을 정리한 뒤 임시 저장소를 제거한다. 각 관측의 임의 지연 제한을 대신해 [XCTest 실행 한도](https://developer.apple.com/documentation/xctest/xctestcase/executiontimeallowance)를 활성화하고 130회 전체에 60초 상한을 둔다. 운영 코드의 시간 제한·재시도 정책을 완화한 것은 아니며, 처리 지연과 실기기 성능 합격 근거는 별도다.

시계 자동 복구, 암호화 이전, 물체 선택·이름 지정과 후속 수정의 통합 판정은 [PR #1의 테스트 결과](https://github.com/L3J-Vispace/Vispace/pull/1)와 해당 head에 연결된 [iOS CI 실행 기록](https://github.com/L3J-Vispace/Vispace/actions/workflows/ios-ci.yml)을 따른다. Core, Debug·Release, 리소스, archive, 시뮬레이터 및 Analyze 전체 결과를 함께 확인하며 개별 단계 통과를 전체 통과로 표현하지 않는다. 실기기 합격 근거는 이 CI와 별개다.

## 영향과 롤백

변경은 로컬 공간 저장, 인식·검색·배치·안내, 앱 생명주기와 설정 화면에 영향을 준다. 저장과 경로 안내의 동작을 바꾸므로 위험도는 높음으로 취급하며 실기기 검수가 끝나기 전 출시 완료를 주장하지 않는다.

문제 발생 시 해당 기능 커밋을 `git revert`하고 CI를 다시 실행한다. 기존 데이터는 먼저 보존한다. `reset --hard`, 강제 push, 이력 재작성은 롤백 방법으로 사용하지 않는다. 직전 metadata 복구본은 앱의 로컬 손상 복구 수단이며 소스 코드 롤백과는 별개다.

시계 복구의 설계와 B08의 남은 조건은 [시간 기록과 재식별 보완 기록](TEMPORAL_RELIABILITY_2026-09-05.md), 실제 기기 합격 조건은 [실기기 검수표](DEVICE_ACCEPTANCE.md)에 있다.
