# 미완성 기능 보고서 후속 구현

첨부 `Vispace 미완성 기능 점검 보고서`의 기준 커밋은 `a5ae285`다. 이번 작업은 그 커밋에서 분기한 `codex/complete-spatial-gaps-20260905`에서 G01–G08의 실제 앱 연결을 보완한다. 보고서에 별도 확장으로 구분된 자유 대화, 미지원 인식 종류, 전체 방 배치 추천, 다층 경로, 전체 이력 내보내기와 자동 동기화는 포함하지 않는다.

G01–G08의 앱 연결과 회귀 테스트를 보완했고, 최신 소스로 iOS 빌드·전체 회귀·정적 분석을 통과했다. 실제 카메라 특징 추출과 파일 보호의 실기기 전용 테스트 2개는 시뮬레이터에서 제외했다. 아래 구현·자동 검증 결과를 실기기 검수나 출시 승인으로 읽으면 안 된다.

## 데이터와 개인정보

카메라 원본 이미지·영상은 계속 일시적으로만 처리한다. G05는 이미지 자체 대신 Vision 특징 벡터와 공간·관측 출처를 `place-visual-evidence-v1.json`에 저장한다. 이 파일도 민감한 로컬 공간 데이터로 취급하며 앱 전용 보호 디렉터리, 백업 제외, 256개 레코드·16MiB 입력 제한을 적용한다. 전체 데이터 삭제와 지도별 삭제에 포함한다. 현재 암호화 내보내기 범위에는 이 파일이 포함되지 않는다.

새 재분류 이벤트와 관계의 관측 출처가 저장 기록에 추가된다. 롤백 때 해당 데이터를 읽지 못하는 이전 앱으로 단순 교체하면 안 된다. 사용 중 데이터와 복구 사본을 보존하고, 새 저널·스냅샷을 읽는 코드는 유지한 채 새 입력과 공급자 연결을 비활성화하는 수정 버전을 배포한다. 암호화 내보내기에 포함되지 않는 장소 특징 파일까지 보존해야 하므로 기존 내보내기 파일 하나를 전체 복구 사본으로 간주하지 않는다.

## 검증 기록

- 보고서 본문·표를 읽고 기준 커밋과 실제 호출 경로를 대조했다. 첨부 문서는 읽기 전용으로 취급했으며 별도 문서 파일로 재작성하지 않았다.
- Swift 소스 161개의 정규화한 SHA-256을 Windows 작업본과 Mac 실행본 사이에서 대조했으며 불일치는 0개다. 코드 커밋은 `dbcbbfa`, `aeb7eb3`, `5d72685`로 나눴다. 중간 커밋별 독립 빌드가 아닌 최종 소스 상태를 검증했다.
- `Scripts/verify-core.ps1 -CleanRecheck`: Core 344개(XCTest 335 + Swift Testing 9), 일반 실행과 정리 후 재실행 모두 통과했다. 최종 Mac 사전 검증에서도 같은 테스트가 통과했다.
- `Scripts/verify-ios.sh`: Xcode 26.6, iOS 26.5 SDK, 새 빌드 디렉터리에서 Debug·Release 시뮬레이터 빌드, 기기용 서명 없는 Archive, Analyze를 통과했다. 모델·한국어 리소스·개인정보 선언과 Release의 테스트 우회 문자열 부재도 확인했다.
- 최종 iPhone 17 시뮬레이터 결과: 489개 중 487개 통과, 2개 제외, 실패 0개다. 제외 항목은 `testRealCameraBufferProducesRevisionPinnedVisionFeatures`와 `testEffectiveFileProtectionOnPhysicalDevice`이며 모두 실제 iOS 기기 검증이 필요하다.
- 우회 인자 없이 Release 앱을 일반 실행해 온보딩 화면, 10초 생존과 새 Vispace 크래시 보고서 0개를 확인했다. 이는 실제 카메라·AR 입력의 통과 증거가 아니다.
- Mac의 최종 검증 결과는 `TestResults/verification-primary.0aEiqh`, 일반 실행 증거는 `TestResults/gaps-launch`에 있다. 수정 전 실패 실행은 최종 통과 건수에 합산하지 않았다.
- 독립 소스 검토와 실제 실행으로 지속 이동, 겹치는 장애물, 오래된 선택, 저장 revision, 테스트의 화면 경계·배열 접근 문제를 보완했다. 진단용 출력이나 프로젝트 전체 경고 완화 설정은 남기지 않았다.

### 검증 중 발견한 크래시

2026-09-05 18:06의 사용자 첨부 크래시 보고서는 자동 테스트 프로세스 `Vispace [14572]`와 일치한다. `testTrackerCadenceCannotCreateMissButEmptyDetectorPassCan`이 생성되지 않은 두 번째 배치를 배열 인덱스로 읽으며 `EXC_BREAKPOINT`로 종료됐다. 테스트의 물체 경계가 깊이 오차 여유를 포함하면 신뢰 가능한 화면 영역을 벗어났기 때문에 새 개별 부재 검증은 해당 관측을 보류했다.

테스트 입력을 전체 경계가 화면 안에 들어오는 조건으로 수정하고, 실패한 개수 검증 뒤에도 배열 접근이 크래시를 내지 않도록 `XCTUnwrap`으로 검사한다. 부재 판단의 실제 화면·깊이 검증은 완화하지 않는다. 분류 정정 테스트는 별도의 이름 변경 계약을 사용하도록 고쳤다. 해당 크래시 테스트와 분류 정정·오래된 관계·시계 역행 관계 테스트는 수정 후 개별 재실행에서 통과했다.

### Vision 실행 환경의 한계

iOS 26.5 시뮬레이터의 GPU 경로는 Espresso 컨텍스트 생성에 실패했다. 지원 CPU 선택, 전체 이미지 입력, 소프트웨어 이미지 변환과 백그라운드 처리의 독립 대조에서도 서로 다른 이미지가 같은 768개 특징값을 만들었으며 Apple의 `computeDistance` 역시 0을 반환했다. 같은 입력을 네이티브 macOS Vision Revision 2로 실행하면 동일 이미지 거리는 0, 다른 이미지 거리는 기본 장치 0.8789407·CPU 0.8652683으로 구별됐다.

따라서 시뮬레이터에서는 특징 추출 결과를 생성하지 않고 보류한다. 실제 iPhone 경로는 Vision을 그대로 사용하며 반환 관측의 revision까지 검사한다. 실제 카메라 버퍼 통합 테스트는 같은 이미지의 엄격한 반복 오차와 다른 이미지의 구별 검사를 유지하고 시뮬레이터에서는 사유를 명시해 제외한다. 이를 물리 iPhone의 입력·장소 식별 검증 통과로 계산하지 않는다.

## 실기기 완료 조건

실제 LiDAR iPhone에서 단독 물체의 연속 관측과 재실행, 동종 실물 교체, 관측 공백 뒤 명시적 연결, 분류 정정 후 관측 지속, 비슷한 방의 정합 보류, 개별 물체 부재, 문 개폐와 통로 철회, 장시간 발열·메모리, 잠금 상태 데이터 보호를 확인한다. 특징 거리·추적·통행 측정의 임계값은 기기와 환경에서 교정해야 하며, 자동 테스트 통과를 공간 정확도나 출시 합격으로 표현하지 않는다.
