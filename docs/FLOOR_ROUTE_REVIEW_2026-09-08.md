## 시각 검증의 범위

기존 서명된 iPhone 빌드 `52a82f5`의 실기기 결과에서 밝고 어두운 합성 바닥의 경로·방향·도착 원이 실제로 표시되는 캡처를 추출해 확인했다. 이는 실제 방의 카메라 가림, 보행 정합, 경로 정확도 검증을 대신하지 않는다.

UIHostingController로 실제 `SpatialQueryPanel`을 밝고 어두운 테마, 기본 및 최대 접근성 글자 크기, 선택 결과 및 실패/재시도 상태에서 캡처했다. 최초 8장에서 본문 잘림을 발견하여 수정했다. 공개 UIKit 접근성 컨테이너는 이 실행 환경에서 SwiftUI의 가상 버튼을 노출하지 않았으므로, 해당 캡처를 실제 탭이나 VoiceOver 동작 검증으로 계산하지 않는다. 캡처 테스트는 빈 화면을 성공으로 취급하지 않도록 실제 안내 버튼 픽셀과 컨트롤러 상태를 검증한다.

최종 코드와 UI 재검토에서 추가로 확정된 결함은 없었다. 새 버튼의 실제 터치·VoiceOver 포커스, 실제 방에서의 보행/가림/위치 정합은 아직 기기 검증이 필요한 항목이다.

Simulator의 RealityKit 합성 장면 캡처는 별도 한계가 남아 있다. GUI 실행, 렌더링 준비 대기, HDR 비활성화를 비교했지만 기본 Unlit box와 SimpleMaterial sphere까지 실제 Simulator 화면에 표시되지 않았다. 카메라·앵커 활성 상태와 투영 좌표는 정상이고 `meshShadowCasterProgrammableBlending` 컴파일 오류가 발생했다. 특정 리본 메시나 snapshot API만의 문제라는 근거는 없으며 정확한 그래픽 파이프라인 원인은 미확정이다. 픽셀 단언을 완화하거나 실패를 성공으로 바꾸지 않았다. Apple도 Simulator와 기기의 [Metal 기능 차이](https://developer.apple.com/documentation/metal/developing-metal-apps-that-run-in-simulator)를 설명한다. 이 문서가 현재 오류의 단일 원인을 입증하는 것은 아니다.
