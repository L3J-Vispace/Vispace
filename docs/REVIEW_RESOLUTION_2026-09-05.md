## R05 저장 형식과 복구

- 그래프 catalog와 map record는 schema 2로 기록하며 schema 1을 읽어 이전한다. schema 2에서 필요한 projection mode가 빠졌거나 미래 schema가 오면 원본 바이트를 보존하고 거부한다.
- 지도별 활성·만료 기하 관계 캐시는 합계 1,024개를 넘으면 on-demand 방식으로 전환한다. 전체 4MiB 한도에도 큰 기하 캐시부터 제거한다. `blocking`, `connectedTo`, `accessibleFrom` 같은 원본 비기하 증거와 그 이력은 제거하지 않는다.
- 비기하 증거만으로도 저장 한도를 초과하면 별도의 보호된 receipt에 해당 지도의 파생 저장 지연과 실패한 base revision을 남긴다. 원본 관측 저장을 계속하고, 비기하 질의는 불완전한 결과를 확정 부정으로 표현하지 않는다.
- receipt는 16KiB·64개 지도 한도로 읽기를 제한한다. 오래된 ACK는 지연 표시를 지우지 않으며, 실패한 base보다 새로운 내구성 있는 revision이 확인돼야 정리한다. 공간을 돌려주는 정리는 일반 쓰기의 128MiB 여유공간 정책과 구분하지만 원자 쓰기에 필요한 공간은 여전히 검사한다.
- 복구 metadata는 operation gate 안에서 전체 항목의 지도·좌표계·revision·이름을 검증한 뒤 한 번만 게시한다. 마지막 항목 실패 시 앞 항목도 게시하지 않는다. 그래프는 반환된 실제 저장 문서로 복구하며, on-demand 또는 용량 지연 상태가 되면 불필요한 나머지 캐시 I/O를 중단한다.

동일 Mac의 밀집 가져오기·복구·다음 저장·cold restart·관계 질의 회귀는 배치 전 약 89.244초, 배치 적용 후 새 빌드에서는 1.028초였다. 앞 실행에는 테스트 fixture의 카메라 구간 ID 불일치도 있어 최종 질의 assertion이 실패했으며, ID를 고정한 뒤 최종 회귀가 통과했다. 이 수치는 특정 256개 fixture의 전체 시험 시간이며 일반적인 성능 보장이나 순수 함수 벤치마크가 아니다.

## 사용자가 전달한 Simulator 종료 보고서

2026-09-05 15:56:23의 `EXC_BAD_ACCESS / SIGBUS`는 로컬 XCTest의 Vispace 호스트에서 발생했다. 검증용 파일 전송 도구가 tar 항목의 수정 시각을 0으로 고정해, 재전송한 graph 소스의 시각이 이전과 같았다. 빌드 로그에서 변경된 `SpatialSceneGraphService.swift`와 `SceneGraphRepository.swift`가 다시 컴파일되지 않은 것을 확인했다. 그 결과 변경된 호출자·테스트와 이전 graph object 파일이 한 실행 파일에 섞였다.

## CI 실행 환경과 비용

사용량 경고 이후 실행 중이던 GitHub-hosted 검증을 취소했다. 사용자의 요청에 따라 비공개 저장소 전용 `vispace-macbook` runner(ID 21)를 일반 사용자 launchd 서비스로 설치했다. GitHub API와 실제 새 job의 runner 이름을 확인했다. 워크플로에는 GitHub-hosted fallback이 없다.

이 실행 시간은 GitHub-hosted 무료 분을 소모하지 않는다. [GitHub Actions 요금 안내](https://docs.github.com/en/billing/concepts/product-billing/github-actions) 현재 main에는 이 워크플로 변경이 아직 없으므로 PR 병합이 필요하다. 서비스 관리, 같은 저장소 PR 제한, 로그인·잠자기 조건과 실패 진단 보존 경로는 [맥북 CI 운영 문서](SELF_HOSTED_CI.md)에 있다.

## 남은 검증과 롤백

실제 iPhone의 AR 재위치·인식·배치·동적 장애물, 잠금 상태의 Data Protection, Files 공급자, 장시간 발열·배터리와 서명된 배포 archive는 이번 Simulator 실행으로 확인하지 못했다. 연결된 실제 iPhone은 검증 시점에 사용 불가 상태였다. 따라서 코드 결함 수정과 실행 회귀 통과를 실기기 검수 또는 출시 완료로 표현하지 않는다.

미배포 브랜치는 문제를 일으킨 작업 단위 커밋을 `git revert`하고 같은 검증을 수행한다. 이미 새 저장 형식이 사용됐다면 원본과 복구 사본을 보존하고 새 schema를 읽는 기능을 유지한 수정으로 되돌려야 한다. 특히 graph schema 2를 지원하지 않는 이전 앱을 그대로 배포하거나 비기하 증거가 포함된 catalog를 삭제하면 안 된다. 검증된 이전 데이터 사본 없이 버전 값을 강제로 바꾸지 않는다.

맥북 runner는 설치 폴더에서 `./svc.sh stop`으로 중지한다. CI 설정을 이전 버전으로 되돌리면 GitHub-hosted 사용량이 다시 발생할 수 있다.
